# Requirements Document: cloudflare-hosting

## Introduction

SoloDayは、一人社長向けのカレンダー統合AIアシスタントです。現在はnpxで実行するローカルアプリケーションとして動作していますが、本仕様では **Cloudflare Pages/Workers** でホスティングされるマルチユーザー対応のSaaS形態への移行を実現します。

これにより、デバイスを問わずどこからでもアクセス可能となり、セットアップの手間を削減し、より多くの一人社長が「今日/今週の自分を30秒で把握」できる体験を提供します。

## Alignment with Product Vision

SoloDayのプロダクトビジョン「複数カレンダーを統合して今日/今週の自分を30秒で把握する」は、本移行においても変わりません。むしろ以下の点でビジョンを強化します。

- **アクセシビリティの向上**: ローカル環境不要でブラウザからすぐに利用開始
- **モバイル対応**: PWA化によりスマートフォンからの素早いアクセス
- **保守性の向上**: Cloudflareのグローバルインフラによる高速・安定稼働
- **セキュリティ強化**: NextAuth.jsによる標準的な認証フロー、D1による安全なデータ管理

既存の「ミーアキャットキャラクター」「シンプルなUX」「AIによる質問応答」といった体験は完全に維持します。

## Requirements

### Requirement 1: Cloudflare Pagesでのホスティング

**User Story:** 一人社長として、ローカル環境のセットアップなしにブラウザからすぐにSoloDayを利用したい。そうすることで、どのデバイスからでも素早くカレンダーにアクセスできる。

#### Acceptance Criteria

1. WHEN ユーザーがプロダクションURLにアクセスする THEN Next.jsアプリケーションが正常に表示される
2. WHEN ユーザーが初回アクセスする THEN 認証画面が表示される
3. IF Cloudflare Pagesでビルドが実行される THEN OpenNext経由でビルドが成功する
4. IF アプリケーションがCloudflare Workersで実行される THEN Node.jsネイティブモジュール依存を含まない形で動作する
5. WHEN ユーザーがページ遷移を行う THEN App Routerのルーティングが正常に機能する

### Requirement 2: マルチユーザー認証（NextAuth.js + D1）

**User Story:** 一人社長として、安全にログインして自分のカレンダーデータだけを閲覧したい。そうすることで、他のユーザーと情報が混在せず、プライバシーが守られる。

#### Acceptance Criteria

1. WHEN ユーザーが未認証状態でアプリにアクセスする THEN ログイン画面にリダイレクトされる
2. WHEN ユーザーがGoogleアカウントでログインする THEN NextAuth.jsがセッションを作成し、メイン画面に遷移する
3. IF ログインセッションが有効である THEN ユーザーは自分のカレンダーデータのみにアクセスできる
4. WHEN ユーザーがログアウトする THEN セッションが破棄され、再度ログイン画面に戻る
5. IF NextAuth.jsがD1データベースを使用する THEN users, sessions, accounts テーブルが適切に作成・利用される
6. WHEN 新規ユーザーがサインアップする THEN D1にユーザーレコードが作成される

### Requirement 3: Google Calendar OAuth マルチテナント対応

**User Story:** 一人社長として、自分のGoogle Calendarアカウントを安全に連携し、他のユーザーのカレンダーと混在しない形で利用したい。そうすることで、複数のユーザーが同じサービスを利用しても各自のデータが独立して管理される。

#### Acceptance Criteria

1. WHEN ユーザーがセットアップ画面でGoogle Calendarを追加する THEN OAuth 2.0フローが開始される
2. WHEN Googleの認証画面で許可を与える THEN アクセストークンとリフレッシュトークンがユーザーごとに安全に保存される
3. IF ユーザーがカレンダーを閲覧する THEN 自分のGoogle Calendarアカウントに紐づいた予定のみが表示される
4. IF 別のユーザーがログインする THEN 異なるGoogle Calendarアカウントに紐づいた予定が表示される
5. WHEN トークンが期限切れになる THEN リフレッシュトークンを使用して自動的に再取得される
6. IF トークンがD1に保存される THEN 暗号化された状態で保存される

### Requirement 4: D1データベースによるデータ永続化

**User Story:** 一人社長として、設定やカレンダーキャッシュがクラウド上に永続化され、どのデバイスからアクセスしても同じ情報が見られるようにしたい。そうすることで、デバイスを切り替えても一貫した体験が得られる。

#### Acceptance Criteria

1. WHEN アプリケーションが起動する THEN D1データベースに接続される
2. IF ユーザーがカレンダー設定を保存する THEN D1のテーブルにユーザーIDと紐づいて保存される
3. IF ユーザーが予定を閲覧する THEN D1のイベントキャッシュテーブルから取得される
4. WHEN カレンダーデータが更新される THEN キャッシュがD1に保存され、次回アクセス時に利用される
5. IF better-sqlite3を使用していたコードがある THEN D1のAPIに置き換えられる
6. WHEN ユーザーが削除される THEN 関連するカレンダー接続情報、キャッシュも削除される（カスケード削除）

### Requirement 5: Web Crypto APIによるシークレット暗号化

**User Story:** 一人社長として、自分のOAuthトークンやAPIキーが安全に暗号化されて保存されることを期待する。そうすることで、万が一データベースが漏洩しても機密情報が保護される。

#### Acceptance Criteria

1. WHEN OAuthトークンがD1に保存される THEN Web Crypto APIで暗号化される
2. IF トークンが取得される THEN Web Crypto APIで復号化される
3. IF node:cryptoを使用していたコードがある THEN Web Crypto APIに置き換えられる
4. WHEN 暗号化キーが必要になる THEN Cloudflare環境変数（Secrets）から取得される
5. IF 暗号化処理が失敗する THEN エラーログが記録され、ユーザーに適切なエラーメッセージが表示される

### Requirement 6: 既存機能の完全互換

**User Story:** 一人社長として、Cloudflare移行後も現在使っているすべての機能（カレンダー統合、AI質問応答、ダークモード等）がそのまま使えることを期待する。そうすることで、学習コストなく移行できる。

#### Acceptance Criteria

1. WHEN ユーザーがメイン画面を開く THEN 今日/今週の予定が統合表示される
2. WHEN ユーザーがAIに質問する THEN Mastra Agentが回答を返す
3. IF ダークモードが有効である THEN UIがダークテーマで表示される
4. WHEN ユーザーが複数のGoogleカレンダーを追加する THEN すべてのカレンダーが統合表示される
5. WHEN ユーザーがiCal URLを追加する THEN iCal形式の予定が取得・表示される
6. IF セットアップフローが完了していない THEN セットアップ画面が表示される

### Requirement 7: PWA対応（モバイルアクセス）

**User Story:** 一人社長として、スマートフォンのホーム画面にSoloDayを追加し、ネイティブアプリのように素早く起動したい。そうすることで、移動中でもカレンダーをすぐに確認できる。

#### Acceptance Criteria

1. WHEN ユーザーがスマートフォンのブラウザでアクセスする THEN PWAインストールプロンプトが表示される
2. WHEN ユーザーがPWAをインストールする THEN ホーム画面にアイコンが追加される
3. WHEN ユーザーがPWAを起動する THEN ブラウザUIなしでアプリが全画面表示される
4. IF manifest.jsonが存在する THEN アプリ名、アイコン、テーマカラーが適切に設定されている
5. IF Service Workerが登録されている THEN オフライン時に基本的なUIが表示される
6. WHEN ユーザーがモバイルでページを閲覧する THEN レスポンシブデザインが適用され、タッチ操作に最適化されている

## Non-Functional Requirements

### Code Architecture and Modularity

1. **DDD（ドメイン駆動設計）の維持**: 既存のドメイン層をインフラ層（D1、Web Crypto API）から分離し、変更の影響を局所化する
2. **関数型プログラミングの継続**: 純粋関数、イミュータブルなデータ構造、Result型/Option型を活用し、副作用を端に追いやる
3. **リポジトリパターン**: データアクセスはリポジトリ経由で行い、D1の実装詳細をドメイン層から隠蔽する
4. **依存性注入**: Cloudflare環境（D1、KV、Secrets）への依存を明示的にし、テスタビリティを確保する

### Performance

1. **初回表示**: ユーザーがログイン後、メイン画面が2秒以内に表示される
2. **カレンダー取得**: 複数カレンダーの統合表示が5秒以内に完了する
3. **AI応答**: ユーザーの質問に対し10秒以内に初回レスポンスが返る
4. **キャッシュ戦略**: カレンダーデータは15分間キャッシュし、不要なAPI呼び出しを削減する
5. **D1クエリ最適化**: インデックスを適切に設定し、N+1問題を回避する

### Security

1. **認証**: NextAuth.jsのセッション管理を使用し、CSRF対策を実施する
2. **OAuth**: Google Calendar連携はread-onlyスコープのみを要求する
3. **暗号化**: OAuthトークンとAPIキーはWeb Crypto APIで暗号化してD1に保存する
4. **環境変数**: 暗号化キーやOAuthクライアントシークレットはCloudflare Secretsで管理する
5. **XSS対策**: ユーザー入力は適切にエスケープし、React/Next.jsの標準的な防御機構を活用する
6. **HTTPS**: すべての通信はHTTPSで暗号化される

### Reliability

1. **エラーハンドリング**: すべての外部API呼び出しは適切なエラーハンドリングを実装する
2. **リトライ処理**: 一時的なネットワークエラーに対しては指数バックオフでリトライする
3. **ログ**: Cloudflare Workersのログ機能を使用し、エラー発生時のトレースを可能にする
4. **フォールバック**: AI応答が失敗した場合、ユーザーに明確なエラーメッセージを表示する
5. **データ整合性**: D1のトランザクションを適切に使用し、データの一貫性を保つ

### Usability

1. **既存UIの維持**: ミーアキャットキャラクター、配色、レイアウトを完全に維持する
2. **レスポンシブデザイン**: スマートフォン、タブレット、デスクトップで最適なUIを提供する
3. **ダークモード**: 既存のダークモード対応を維持する
4. **エラーメッセージ**: ユーザーフレンドリーな日本語エラーメッセージを表示する
5. **ローディング表示**: 長時間かかる処理には適切なローディングインジケーターを表示する
